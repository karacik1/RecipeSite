# 🗺️ Roadmap проекта

## 🥇 Этап 1: Довести до MVP (2–3 недели)

**Цель:** работающее приложение, которое можно показать.

- [ ] Профиль пользователя (просмотр, редактирование)
- [ ] Главная страница со списком рецептов
- [ ] Навигация (шапка, меню, вход/выход)
- [ ] Валидация форм
- [ ] Сообщения об успехе/ошибке (`messages framework`)
- [ ] Регистрация / логин / логаут
- [ ] Базовый CSS (Bootstrap или Tailwind)

**Что учить:** Django `auth`, `forms`, `messages`, шаблоны, `static`.

**Результат:** можно показать другу, он поймёт, что делать.

---

## 🥈 Этап 2: Linux (1–2 недели)

**Цель:** перестать бояться терминала, понять, как работает сервер.

**Что учить:**
- [ ] Основные команды: `ls`, `cd`, `cp`, `mv`, `rm`, `cat`, `grep`, `find`, `chmod`, `chown`
- [ ] Процессы: `ps`, `top`, `htop`, `kill`
- [ ] Сеть: `curl`, `wget`, `ping`, `netstat`, `ss`
- [ ] Права доступа, пользователи, `sudo`
- [ ] Пакетные менеджеры: `apt`
- [ ] SSH: подключение к серверу, ключи
- [ ] Логи: `journalctl`, `/var/log/`
- [ ] Systemd: `systemctl`, `service`

**Через проект:**
- [ ] Поставить Ubuntu в VirtualBox или WSL
- [ ] Склонировать туда проект
- [ ] Запустить `python manage.py runserver`
- [ ] Настроить так, чтобы работало

**Результат:** понимание, что происходит «под капотом» сервера.

## 🥉 Этап 3: PostgreSQL вместо SQLite (1 неделя)

**Цель:** перейти на «взрослую» БД.

**Что учить:**
- [ ] Установка PostgreSQL
- [ ] Создание базы, пользователя, пароля
- [ ] Подключение Django через `psycopg2`
- [ ] `pg_dump` / `pg_restore` — бэкапы
- [ ] Основы SQL: `SELECT`, `INSERT`, `UPDATE`, `DELETE`, `JOIN`

**Через проект:**
- [ ] Перенести данные из SQLite в PostgreSQL
- [ ] Убедиться, что всё работает

**Результат:** проект на «взрослой» БД.

## 🏅 Этап 4: Docker (2–3 недели)

**Цель:** упаковать проект в контейнеры.

**Что учить:**
- [ ] Что такое образ, контейнер, volume, network
- [ ] `Dockerfile` — как собрать образ
- [ ] `docker-compose` — как запустить несколько сервисов
- [ ] `.dockerignore`
- [ ] Volume — чтобы данные не терялись
- [ ] Слои и кэш

**Через проект:**
- [ ] Написать `Dockerfile` для Django
- [ ] Написать `docker-compose.yml` с Django + PostgreSQL
- [ ] Запустить проект **одной командой**: `docker compose up`
- [ ] Убедиться, что данные сохраняются в volume

**Результат:** проект запускается **одной командой** на любой машине.

## 🏆 Этап 5: Redis + Celery (3–4 недели)

**Цель:** фоновые задачи.

**Что учить:**
- [ ] Что такое брокер, worker, очередь
- [ ] Redis как брокер и кэш
- [ ] Celery: `@shared_task`, `.delay()`, `.apply_async()`
- [ ] Celery beat — периодические задачи
- [ ] Мониторинг: Flower

**Через проект:**
- [ ] Парсинг рецептов — вынести в фоновую задачу
- [ ] Удаление старых заявок — через Celery beat (раз в день)
- [ ] Отправка email — через Celery
- [ ] Кэширование списка рецептов — через Redis

**Результат:** понимание, зачем нужны фоновые задачи.

## 🎯 Что важно понимать

### 1. Не учите всё сразу
Одна технология за раз. Изучили → применили → перешли к следующей.

### 2. Технология без проблемы — бесполезна
> ❌ «Я хочу изучить Docker»
> ✅ «Я хочу, чтобы проект запускался одной командой на любой машине»

### 3. Проект — это «скелет»
Каждая новая технология наращивает функциональность.

### 4. Резюме важнее кода
На собеседовании спросят:
- «Расскажи, как ты деплоил проект?»
- «Зачем тебе Redis?»
- «Как ты организовал фоновые задачи?»
